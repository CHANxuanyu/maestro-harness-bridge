# v1.0.1-hb.6 · 三家 AI 接着做，偏好与对话留得住

本候选面向在 Codex、Claude Code 和 DeepSeek 之间工作的用户，集中补齐换家继续、偏好同步、退出保存和日常对话操作。hb.5 从未打标签或发布，编号作废；hb.6 是 hb.4 之后拟发布的第一个公开包，目前仅完成源码候选准备，尚未构建或发布。

## 产品变化

- 新建智能体可以直接选 DeepSeek，界面显示对应名称与预设模型，密钥按现有方式遮盖。通过 Claude Code 的兼容接口运行，独立保存历史，不混入 Claude 账户。
- 对话菜单、命令面板和额度、限流、登录失效的错误旁可以“换个 AI 继续”。在同项目目标智能体的新标签中准备可编辑的交接草稿，展示来源、大小与省略量；按发送才开始，原对话不变。CLI 与界面共用同一流程。
- “关于我”保存完整 Markdown，并可逐文件确认同步到三家的本机原生指令文件。保留其他内容，外部改动后重新确认，按文件报告写入与失败；已确认同步的内容在普通对话启动时改用原生指引，减少重复注入。
- 退出前协调所有窗口保存最后的会话变化。历史接续保留原生首条用户请求、模型、工具结果与停止状态；跨应用追加能只读跟随，长历史和符号链接项目的读取也已改进。这包含原 hb.5 未发布候选积累的改动。
- 对话使用比例字体、Clay 深浅主题与可收起的文件栏；输入框集中常用控制，侧栏顶部能新建会话，标题减少会话 ID。当前对话运行时发送变停止，Esc 停止并保留草稿，对话末尾显示运行状态；后台任务单独提示，正在看的对话结束时不再弹摘要通知。
- 项目历史会列出同一仓库 Git worktree 里的 Claude Code 和 Codex 对话，包括 `.claude/worktrees` 下已经移除的目录；压缩保存的 Codex 历史也能打开、搜索和跟随。命令行新增 `native-history list|read|delete`。

完整范围见[产品 changelog](../../CHANGELOG.md)。上述为候选行为，发行包上的通过结果须按[hb.6 验收记录](../verification/v1.0.1-hb.6.md)逐项补齐。

## 下载、升级与启动

发布后从[本仓库 Releases](https://github.com/CHANxuanyu/maestro-harness-bridge/releases)下载 `Maestro-I18n-1.0.1-hb.6-mac-arm64.zip` 并核对 `SHA256SUMS.txt`。仅提供 Apple Silicon macOS 安装包；Linux 和 Windows CI 不是这两个平台的安装包验收。应用采用临时签名，未做 Apple Developer ID 公证。

正常结束任务与队列，退出旧版，备份 `~/Library/Application Support/Maestro I18n` 及自定义存储位置，再解压替换应用。不要同时运行两个同名版本；首次打开按 macOS“隐私与安全性”的系统提示确认。应用名 `Maestro I18n`、bundle ID `com.maestro.i18n.local` 保持不变，沿用既有配置，手动从本仓库更新。新设置沿用原有存储；本轮候选准备没有新增配置迁移。

原生 CLI 仍须自行安装并登录，Maestro 不提供统一认证或共享额度。真实模式锁定 Claude Code `2.1.310`、Codex CLI `0.163.0-alpha.11.1`，直接来源为 [`real-runtime.cjs` 的 versions 表](../../e2e/fixtures/native/real-runtime.cjs)；DeepSeek 也使用该 Claude Code 版本，并需要自己的 API 凭据。版本决定见[hb.6 前置项](../verification/hb6-prerequisites.md#codex-依据与版本决定)。不随桌面自动更新改变测试基线，其他提供方沿用锁定表和[原生契约](../native-provider-contracts.md)的边界。

共享连接器为独立附件 `Maestro-Codex-Shared-1.0.1-hb.6.zip`，替换应用不会自动启用它。相对 hb.4，累计改动包含命令输出增量、回合隔离、失败与停止状态及版本检查；本轮未改连接器，也未扩大准入。[版本清单](../../scripts/codex-shared/versions.json)仍只有 `codex-cli 0.163.0-alpha.11.1` 标为 admitted，其他 candidate 不代表日常可用。按[双端说明](../codex-shared.md)正常退出并检查版本后再选择启用；新包必须重新实测，不能引用旧包结果代替。

回退目标是[上一公开版 hb.4](https://github.com/CHANxuanyu/maestro-harness-bridge/releases/tag/v1.0.1-hb.4)，不是作废的 hb.5。先结束任务与队列、正常退出，另存当前配置，再恢复 hb.4 应用和升级前配置备份。新建的 DeepSeek 配置、交接草稿及新设置需先另存，旧版不保证理解这些字段。如果同步过“关于我”，原生指令文件独立于应用配置，回退应用不会撤销写入；需要撤销时先在 hb.6 中检查并确认清除管理段，或从自己保存的原生文件备份恢复，保留段外内容。换过连接器的用户先按双端说明运行相应目录的 `disable-sharing.command`，恢复旧自定义可执行路径与连接器。不要删除原生历史或写锁。

## 验证与已知限制

2026-11-05 重新打包：hb.6 未打标签，候选在 PR #45、#46 合入后重新冻结。构建来源是本次候选 PR 合并后的主线提交，完整 commit 与主线 CI 记在[验收记录](../verification/v1.0.1-hb.6.md)。2026-11-03 起点 `0c15c18f5eef5cc17aec6387fd1797973f7b5d92` 上的源码检查与开发构建真实模式只作背景，见[工作记录](../worklog.md#2026-11-03hb6-候选与-windows-账户路径回归)。

真实模式和发行包 GUI 均为待执行，没有发行包、签名或包内 SQLite/PTY 的新通过证据。旧 hb.4 包与 hb.5/各功能开发构建记录只作背景，不复用为本版验收结果。源码检查通过不代表可发布。

- 运行中的应用里用 `maestro-cli settings set` 改设置时，若恰好紧跟应用自身的一次设置写入（半秒内），窗口可能不更新，需要再改一次或重启；下一版修复。
- 共享只限同账户、同主机的已有本地 Codex 会话顺序接续，不支持并发写入、新建、分支或远程共享。SSH 历史仍按配置主机读取；DeepSeek 预设、跨 AI 交接和关于我同步的本轮范围均为本机。
- 固定版本普通 Codex exec 在命令完成时提供输出，运行中命令增量只属于共享模式。Stop 中断原生回合，不保证已启动的终端进程立即退出。原生 active writer 拒绝仍需实机复验，不自动重试或删除锁。
- 退出保存有总时限 5 秒，失败或超时会记录后继续退出，不保证失去响应的窗口已保存。两个窗口同时有尾部改动、更新退出及无响应窗口仍需发行包核对。
- 交接只携带文本和工具摘要，不复制图片、附件或原生会话 ID；可用目标不代表凭据与额度已实测。DeepSeek 真实网关、关于我被三家原生 CLI 加载及长历史实际绘制性能均待验。
- 关于我逐文件写入，不承诺跨文件事务或跨进程锁。原生检查只说明当时文件状态，不证明运行中的模型即时重载；需重启原生 CLI。Codex override 优先，未知状态保留提示正文；新建向导和 `/wizard` 仍带全文。
- 既有界面缺口保留给 Opus：删除 DeepSeek 智能体后再开遗留历史可能建成普通 Claude 执行者；Codex 会话浏览器预览仍可能显示系统封装；侧栏尚不区分交接草稿标签。复现步骤见[验收记录](../verification/v1.0.1-hb.6.md#交给-opus-的界面复现)。本轮未修改界面。
- Claude API 摘要遇到残留 thinking 空壳被拒时仍走 `Synopsis failed`，不自动重试或改成本地摘要；下一次正常 API 回合会清理该空壳。其他提供方与冻结功能未扩大承诺。
