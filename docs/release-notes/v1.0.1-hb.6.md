# v1.0.1-hb.6 · 三家 AI 接着做，偏好与对话留得住

本版本面向在 Codex、Claude Code 和 DeepSeek 之间工作的用户，集中补齐换家继续、偏好同步、退出保存和日常对话操作。这是公开预览版。hb.5 从未打标签或发布，编号作废，hb.6 是 hb.4 之后的第一个公开包。

## 产品变化

- 新建智能体可以直接选 DeepSeek，界面显示对应名称与预设模型，密钥按现有方式遮盖。通过 Claude Code 的兼容接口运行，独立保存历史，不混入 Claude 账户。
- 对话菜单、命令面板和额度、限流、登录失效的错误旁可以“换个 AI 继续”。在同项目目标智能体的新标签中准备可编辑的交接草稿，展示来源、大小与省略量；按发送才开始，原对话不变。CLI 与界面共用同一流程。
- “关于我”保存完整 Markdown，并可逐文件确认同步到三家的本机原生指令文件。保留其他内容，外部改动后重新确认，按文件报告写入与失败；已确认同步的内容在普通对话启动时改用原生指引，减少重复注入。
- 退出前协调所有窗口保存最后的会话变化。历史接续保留原生首条用户请求、模型、工具结果与停止状态；跨应用追加能只读跟随，长历史和符号链接项目的读取也已改进。这包含原 hb.5 未发布候选积累的改动。
- 对话使用比例字体、Clay 深浅主题与可收起的文件栏；输入框集中常用控制，侧栏顶部能新建会话，标题减少会话 ID。当前对话运行时发送变停止，Esc 停止并保留草稿，对话末尾显示运行状态；后台任务单独提示，正在看的对话结束时不再弹摘要通知。
- 项目历史会列出同一仓库 Git worktree 里的 Claude Code 和 Codex 对话，包括 `.claude/worktrees` 下已经移除的目录；压缩保存的 Codex 历史也能打开、搜索和跟随。命令行新增 `native-history list|read|delete`，其中 `delete` 仅支持 Codex。
- 智能体换窗口时带上完整对话和草稿。关闭窗口或把智能体移到已打开的窗口后，对话不再显示成空白，也不会被第一次改动覆盖。

完整范围见[产品 changelog](https://github.com/CHANxuanyu/maestro-harness-bridge/blob/df8da1690a847efb6b0d33b6cb20687953ad244d/CHANGELOG.md)。实测范围见下方验证结果，未覆盖的项目不算通过。

## 下载、升级与启动

从[本仓库 Releases](https://github.com/CHANxuanyu/maestro-harness-bridge/releases)下载 `Maestro-I18n-1.0.1-hb.6-mac-arm64.zip` 并核对 `SHA256SUMS.txt`。仅提供 Apple Silicon macOS 安装包；Linux 和 Windows CI 不是这两个平台的安装包验收。应用采用临时签名，未做 Apple Developer ID 公证。

正常结束任务与队列，退出旧版，备份应用配置目录及自定义存储位置，再解压替换应用。不要同时运行两个同名版本；首次打开按 macOS“隐私与安全性”的系统提示确认。应用名 `Maestro I18n`、bundle ID `com.maestro.i18n.local` 保持不变，沿用既有配置，手动从本仓库更新。本版没有新增配置迁移。

原生 CLI 仍须自行安装并登录，Maestro 不提供统一认证或共享额度。真实模式锁定 Claude Code `2.1.310`、Codex CLI `0.163.0-alpha.11.1`，直接来源为 [`real-runtime.cjs` 的 versions 表](https://github.com/CHANxuanyu/maestro-harness-bridge/blob/df8da1690a847efb6b0d33b6cb20687953ad244d/e2e/fixtures/native/real-runtime.cjs)；DeepSeek 也使用该 Claude Code 版本，并需要自己的 API 凭据。版本决定见[hb.6 前置项](https://github.com/CHANxuanyu/maestro-harness-bridge/blob/df8da1690a847efb6b0d33b6cb20687953ad244d/docs/verification/hb6-prerequisites.md#codex-依据与版本决定)。不随桌面自动更新改变测试基线，其他提供方沿用锁定表和[原生契约](https://github.com/CHANxuanyu/maestro-harness-bridge/blob/df8da1690a847efb6b0d33b6cb20687953ad244d/docs/native-provider-contracts.md)的边界。

共享连接器为独立附件 `Maestro-Codex-Shared-1.0.1-hb.6.zip`，替换应用不会自动启用它。相对 hb.4，累计改动包含命令输出增量、回合隔离、失败与停止状态及版本检查；准入范围没有扩大。[版本清单](https://github.com/CHANxuanyu/maestro-harness-bridge/blob/df8da1690a847efb6b0d33b6cb20687953ad244d/scripts/codex-shared/versions.json)仍只有 `codex-cli 0.163.0-alpha.11.1` 标为 admitted，其他 candidate 不代表日常可用。按[双端说明](https://github.com/CHANxuanyu/maestro-harness-bridge/blob/df8da1690a847efb6b0d33b6cb20687953ad244d/docs/codex-shared.md)正常退出并检查版本后再选择启用。

回退目标是[上一公开版 hb.4](https://github.com/CHANxuanyu/maestro-harness-bridge/releases/tag/v1.0.1-hb.4)，不是作废的 hb.5。先结束任务与队列、正常退出，另存当前配置，再恢复 hb.4 应用和升级前配置备份。新建的 DeepSeek 配置、交接草稿及新设置需先另存，旧版不保证理解这些字段。如果同步过“关于我”，原生指令文件独立于应用配置，回退应用不会撤销写入；需要撤销时先在 hb.6 中检查并确认清除管理段，或从自己保存的原生文件备份恢复，保留段外内容。换过连接器的用户先按双端说明运行相应目录的 `disable-sharing.command`，恢复旧自定义可执行路径与连接器。不要删除原生历史或写锁。

构建来源是 PR #54 的合并提交 `df8da1690a847efb6b0d33b6cb20687953ad244d`，[主线 CI 42126474294](https://github.com/CHANxuanyu/maestro-harness-bridge/actions/runs/42126474294) 七项全部通过。验证日期是 2026 年 11 月 6 日，平台是 Apple Silicon macOS。

- **本机检查：** 类型、ESLint、格式和文档引用全部通过。单元测试 47941 通过、88 跳过，Electron 合成场景 76 通过，发布策略 11、连接器合成测试 26、合成夹具 53 全部通过。
- **安装包：** ZIP 完整性和临时签名验证通过。包内 SQLite 查询和 PTY 实际执行通过，包内 CLI 的版本、配置读写和拒绝写入上游数据目录检查通过。隐私扫描覆盖源码 5833 个文本文件和包内 472 个文件，没有私密内容命中；包内 5 个凭据形状的字符串来自原版 Electron。
- **真实模型：** 跑在同一提交的开发构建上，不是安装包。选定的 6 条场景一次通过，覆盖 Codex 压缩历史、两家 worktree 历史、两家同一会话两轮接续和 Claude 项目别名历史。
- **安装包界面：** 对象是发布 ZIP 解压的副本。41 个脚本场景一次通过，用的是模拟提供方和临时数据，不调用模型，也不是人工逐项操作。其中包括两窗口退出、换窗口和重启后回答与草稿仍在。
- **共享连接器：** ZIP 完整性、语法和 13 个载荷文件核对通过。验证机器上的 `codex-cli 0.166.0-alpha.6` 不在准入清单上，自检拒绝启动，所以共享模式没有实测，也没有启用。

下面这些没有验证，不算通过：

- DeepSeek 真实网关（没有密钥），以及三家原生 CLI 实际加载“关于我”偏好。
- 完整真实模型套件，交接和共享连接器的真实场景，以及安装包上的真实模型运行。
- 完整的跨应用写入序列，新包上打开真实的 worktree 历史和压缩历史。对应的合成场景和开发构建上的真实模型场景已通过。
- 连续几天的日常使用，以及真实限流或登录失效时的交接入口。
- 界面上的部分入口和显示：退出时未发送的队列、标签菜单里的交接入口、“关于我”关闭重开和 token 显示、缺失目录的页面、旧配置升级后的外观、另一个智能体运行时的停止控件、运行状态的 token 与通知、真实系统外观切换。
- 更新退出路径和无响应的副窗口，这两项只有单元测试覆盖。
- 移动进行中的回合，以及长历史的实际绘制性能。

## 已知限制

- 运行中的应用里用 `maestro-cli settings set` 改设置时，若恰好紧跟应用自身的一次设置写入（半秒内），窗口可能不更新，需要再改一次或重启。计划下一版修复。
- 窗口保存规则只管桌面窗口。浏览器客户端不属于任何窗口，同一智能体同时在桌面和浏览器里改，或多个浏览器客户端同时改，仍以后写入者为准。
- 全新配置目录下启动后很快退出，Claude 用量探针和它的 `claude` 进程可能留在后台，需要手动结束。计划下一版修复。
- 共享只限同账户、同主机的已有本地 Codex 会话顺序接续，不支持并发写入、新建、分支或远程共享。SSH 历史仍按配置主机读取；DeepSeek 预设、跨 AI 交接和“关于我”同步的范围均为本机。
- 原生对话自动跟随只覆盖当前可见且空闲的本机标签；隐藏窗口、SSH 会话以及正在写入、排队或等待自动恢复的标签不在该轮询范围。
- 固定版本普通 Codex exec 在命令完成时提供输出，运行中命令增量只属于共享模式。原生 active writer 拒绝仍需实机复验，不自动重试或删除锁。
- Stop 按智能体停止，也会停止该智能体内其他运行中的对话，并且不保证已启动的终端进程立即退出。
- 退出保存有总时限 5 秒，失败或超时会记录后继续退出，不保证失去响应的窗口已保存。
- 换窗口时的保存最多等待 3 秒，保存失败或超时后移动仍会继续，不保证出故障的窗口最后的变化已保存。
- 交接只携带文本和工具摘要，不复制图片、附件或原生会话 ID；可用目标不代表凭据与额度已实测。
- “关于我”逐文件写入，不承诺跨文件事务或跨进程锁。原生检查只说明当时文件状态，不证明运行中的模型即时重载，需要重启原生 CLI。Codex override 优先，未知状态保留提示正文；新建向导和 `/wizard` 仍带全文。
- 已知界面缺口：删除 DeepSeek 智能体后再开遗留历史可能建成普通 Claude 执行者；Codex 会话浏览器预览仍可能显示系统封装；侧栏尚不区分交接草稿标签。
- Claude API 摘要遇到残留 thinking 空壳被拒时仍走 `Synopsis failed`，不自动重试或改成本地摘要；下一次正常 API 回合会清理该空壳。
