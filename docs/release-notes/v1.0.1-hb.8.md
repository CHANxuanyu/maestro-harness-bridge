# v1.0.1-hb.8 · 团队群聊、自动跟进与新日常界面的试用候选

这是第二轮开发的试用候选。核心是团队群聊：一个想法交给 PM、开发、QA 三个岗位（每个岗位任选 Claude Code 或 Codex 的模型和强度），团队自己讨论、分工、跑检查、评审，只在越过边界时才问你。单条对话增加了应用自己执行的检查和定时、命令、CI 跟进。新界面的模型选择器、活动条、交付条和左栏标题都按第一轮反馈重做。新界面默认仍关闭，旧界面和旧群聊照常可用（PRD 7.5）。

## 产品变化

- **团队群聊（M1 到 M3）。** 左栏"新建团队"：写一句想法，给三个岗位选模型，设截止时间和回合预算，勾选一次性授权（运行检查、在任务分支提交推送、开草稿 PR、成员故障时临时接任，默认都勾）。PM 写需求，开发和 QA 各自质询，PM 逐条回答，应用先试跑检查，再出基线卡给你确认。确认后开发和 QA 并行，QA 只能写 `qa/`，应用自己跑检查、按证据计数，PM 对着真实产出评审，全部达标才出演示卡，否则出未完成报告。团队内部分歧走四步讨论，按决定层级由 PM 或你拍板；改写已确认标准、放宽或删除标准、改证明方式必须你批。额度用尽、登录失效、会话损坏等八种成员故障有固定的恢复顺序（替补、授权内临时接任、等待重置），三种限度（单次等待、三次无进展强制诊断、回合预算和截止）保证不空转。暂停、继续、重启后按派发记录对账，不重复执行。右侧六个页签：产出、进展、决定、证据、成员（含每个席位的费用）、改动。所有操作都有 `maestro-cli team` 对应命令。
- **单条对话的检查与跟进（B4）。** "检查"页登记验收命令，按项目授权一次；项目内的测试命令（`npm test`、`node --test`、`pytest`、`go test`、`cargo test` 等）之后不再逐次询问，访问项目外或联网写入的命令单独请示。改了文件的回合结束后应用自己跑检查，交付条显示"N/M 通过"和失败输出；发回去修复时按与团队相同的进展规则判断，三次无进展强制诊断，只有越过边界才出升级卡片。"跟进"页登记定时、命令结束或 CI 跟进，落盘保存，重启后照样回到原对话，忙时排队；助手也能从自己的终端用 `maestro-cli follow-up add` 登记。
- **模型与强度选择器（B1）。** 按厂商目录列出模型、说明、默认模型和各自档位，按对话和账号记住选择；只用键盘 7 次按键内换模型和强度。
- **活动条与交付条（B2）。** 运行中只有固定两行活动条，结束后折叠成"用时、步骤数"，展开看明细；回合末尾的交付条显示本回合改了几个文件和增删行数，点开改动面板筛到这一回合；任务清单如实显示。
- **左栏（B3）。** 对话标题从中间省略，保留区分部分；worktree 只留小标记。
- **重启后的计划（R2.0）。** Codex 新版计划记录重启后仍在任务页。

完整条目见 [CHANGELOG](../../CHANGELOG.md)。

## 下载、升级与启动

本候选尚未构建、打标签或上传。候选 PR 合入且主线 CI 全绿后，从冻结提交构建 macOS Apple Silicon 试用包，包名、字节数和 SHA-256 以[候选验证](../verification/v1.0.1-hb.8.md)补写的实际结果为准。

1. 校验 `SHA256SUMS.txt`。正常退出 Maestro，备份当前应用配置和旧应用副本，再替换 `Maestro I18n.app`，不要同时启动两个同名版本。
2. 从 Finder 打开，先核对关于页版本 `1.0.1-hb.8`、原项目、历史和草稿。
3. 在"设置 → 显示 → 新界面"打开，或执行 `maestro-cli settings set newShell true`，无需重启。团队入口在新界面左栏。
4. Claude Code、Codex 仍需各自安装和登录，团队席位使用你原有的账户与额度。

回退界面：关闭同一个开关，或 `maestro-cli settings set newShell false`。回退应用：正常退出，另存当前配置，再恢复上一个已验证的安装包。

## 验证与已知限制

- 合成 Electron：团队 40 个场景在每轮修复后通过；B4 合入前主线全套原生场景 230 项通过。
- 真实模型：V-1 通过，PM 与开发 Codex、QA Claude，中等任务 12 个回合、5.4 分钟，老板只确认基线和验收。M2-10 中较轻的开发模型反复故障后由 Codex 临时接任并完成验收；PM 打回与收敛没有在真实运行中出现。
- 性能：选择器打开达标（中位数 42.5 毫秒）；流式输出时的按键等待未达到 85.7 毫秒的历史记录（本次 93.8 毫秒，改动前同轮 144.4 毫秒）。
- 交付前走查发现的问题已在 #98 修复。包内验证在构建后进行。

详细结果见[候选验证](../verification/v1.0.1-hb.8.md)。

| 限制及触发条件           | 影响                                                                     | 绕过办法                   |
| ------------------------ | ------------------------------------------------------------------------ | -------------------------- |
| 新界面默认关闭           | 团队、检查与跟进只在新界面出现                                           | 在设置里打开               |
| 第三家厂商担任团队岗位   | 未覆盖：没有可用密钥；Antigravity CLI 无法强制只读回合，不能担任团队席位 | 用 Claude Code 或 Codex    |
| SSH 项目的团队           | 本轮不支持，界面会说明                                                   | 在本机项目里建队           |
| 流式输出时的按键等待     | 未达到 85.7 毫秒的历史记录                                               | 长输出时稍等再输入         |
| 切成默认与删除旧界面     | 按 PRD 7.5 要等老板本人走查通过                                          | 无                         |
| 较轻模型担任中等任务开发 | 上下文不够，会由团队已有模型临时接任                                     | 开发选更强的模型，或设替补 |
| 用户消息里的 @提及       | 按输入原样显示为文字，不画成标签                                         | 无影响                     |
