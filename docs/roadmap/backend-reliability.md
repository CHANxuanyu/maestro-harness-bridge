## 工作清单与验收目标

| 工作                              | 当前依据与拟做内容                                                                                                                                                  | 验收目标                                                                                                                                                                       |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1. 工具输入在实时与历史读取中一致 | 已复现：实时解析只读取 `arguments`，原生 `custom_tool_call.input` 会丢失；历史读取已支持该字段。修正现有解析入口，保持字段优先级一致。                              | 补丁原文、JSON 参数、结构化输入和空字符串均原样或按既有 JSON 规则解析；同一调用在运行时和重新加载后输入一致，调用 ID 不变。                                                    |

| 4. 历史增量读取与完整读取一致     | 已有实现，先复验。关注长会话、半行 JSON、中文字符分段写入、工具结果后到、文件截断或替换。                                                                           | 相同文件内容经增量和完整读取，消息顺序、ID、工具输入/结果/状态一致；无重复、无漏项；读取不改写原生历史；正常追加不退化为每次重读整份历史。只有失败用例才触发修改。             |
| 5. 保持原生会话、账户和主机边界   | 已有实现，先复验。同一 ID 在不同账户下分别读取；远程不可用时保持明确失败；忙碌或已有队列时保持现有拒绝发送行为。                                                    | 不串账户、不把远程请求改成本地请求；不新建或分叉会话来掩盖接续失败；不复制历史、不删除写锁、不另起写入者；现有队列不被修改。没有证据的边界不额外加校验。                       |
| 6. 停止后恢复与重启接续           | 先运行现有进程、解析器和连接器回归，再在可用的真实环境验证同一条已有会话。需要区分自动测试与真实应用结果。                                                          | 多轮对话、两次独立工具、停止、停止后继续、正常重启后继续使用同一原生会话；已完成工具保留正确结果，旧错误不清除会话关联。后台命令是否立即退出按实测记录，不扩大停止机制的承诺。 |

第 1、2、3 项是有代码依据和合成复现的修复项。第 4、5、6 项是已有能力的验证项，不预设需要重写。真实应用中的发生频率尚未测量，不能把合成复现说成用户环境实测。

## 实施范围

- 主要入口：`src/main/parsers/codex-output-parser.ts`、`scripts/codex-shared/shared-exec.cjs`，以及对应测试。
- 历史、账户和进程模块仅在验证确认问题后修改，复用现有存储适配器和状态转换函数。
- 本轮不改 `src/renderer/`、`src/web/` 的页面、组件、样式、布局、交互或折叠规则。滚动锚点、未读计数、键盘焦点和视觉密度仍属于前端事项。
- 暂不扩展到所有提供方，不升级 Codex，不引入新共享协议，不改认证和订阅，不做仓库治理或安装包发布。
- 若修复必须涉及前端语义，先记录依赖和原因，不越过本轮边界继续实现。

## 特殊要求

1. **拒绝过度防御性编程。** 每个新增分支必须对应已确认的输入契约、可复现故障或现有需求。不给假设中的损坏、未知版本和不存在的调用方堆备用路径。
2. **不新增哈希或校验体系。** 不为消息、回合、历史或测试证据增加内容哈希、指纹、签名、身份清单和多层一致性检查；不引入“全量扫描 + 哈希比对”轮询。关联继续使用已有原生会话 ID、回合 ID 和工具调用 ID。
3. **不把现有哈希机制的清理混进来。** 仓库已有的发布附件校验和历史读取机制不是本轮的重构目标；本轮不扩充这些机制，也不为完成一个修复新增构建清单或证据平台。
4. **优先最小修改。** 在实际出错的转换或事件入口修复。优先复用 `codexToolResultStatus()` 等已有函数；不为几个条件分支新建框架、通用状态机或多层适配器。
5. **错误语义如实传递。** 不静默吞错，不把缺失结果伪装成成功，不通过重试、回退到另一个账户或另建会话制造“恢复成功”。用户输出中的普通文字不作为状态控制指令。
6. **测试验证行为。** 为已确认缺陷补能先失败、修复后通过的回归；复用现有数据和测试工具。验证输入、输出、顺序、状态及必要的副作用，不用大量快照或照抄实现的断言凑数量。
7. **限制改动与证据量。** 不顺手重构、不升级依赖、不清理无关代码。完成记录只写问题、改动、实际测试结果和未验项，保持简短，不引入额外的审批或验收系统。

## 执行顺序

## 后续后端加固

用户进一步要求为产品路线图提供扎实的后端能力。本阶段沿用上述限制，检查信息流从原生事件到进程退出的完整路径，不以新增框架或代码量作为完成标准。

| 工作                   | 已确认依据                                                                                                            | 验收目标                                                                                                              |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| 退出时的事件完整性     | 相同原生消息，有换行时通过，无末尾换行时丢失工具完成、进度、并行工具结果和用量；已用真实 Codex / Claude 解析器复现。  | 有无末尾换行的事件内容、调用关联和结束顺序一致；所有结果先于退出送达，最终答案只发送一次。                            |
| 错误恢复的先后顺序     | 无末尾换行的恢复消息尚未处理，退出路径就把暂存错误报告为最终失败；已复现。                                            | 先处理最后一条消息再判定暂存错误；真实恢复不误报，未恢复的失败仍按输出、错误、退出的顺序发送；Stop 与旧进程隔离保持。 |
| 工具流式更新与终态     | Codex exec 的命令 `item.updated` 被当成未知消息，运行中更新也会被重复开始去重拦截；取消未从活动调用集合移除。已复现。 | 命令中间输出沿用原调用 ID，普通重复开始仍去重，完成与取消正确收束；保留既有回合和进程隔离。                           |
| Copilot 最终答案优先级 | 统一退出分发时补充验证，发现尾部消息与增量能覆盖或拼接到磁盘最终答案。                                                | 先处理尾部事件，再应用磁盘最终答案；消息、增量和最终答复三类尾部内容均不替换更晚完成的磁盘结果。                      |
