# 界面改版：向 Claude Code 看齐

状态：用户 2026-11-02 定下方向（“这个界面完全依托狗屎，不如直接模仿 Claude Code”），并要求 Opus 作为 PM 持续交付、不必逐步等确认。本文是改版的设计说明和分阶段计划，每阶段一个 PR，叠在当前 PR 链（#32 至 #37）之上。

## 现状审查

2026-11-02 用假程序跑一段真实对话（两轮回答，含工具调用、Markdown 和代码块，第三轮运行中），在深色默认主题和 GitHub 浅色主题下各截了全窗口图。问题按观感影响排序：

1. **全部等宽字体。** 界面、对话、标题都是 JetBrains Mono，看起来像终端而不是对话工具。仓库里已有“比例字体读、等宽字体写”的 Default 预设，但存储默认值仍是全等宽。
2. **右栏默认展开。** 文件、历史、自动运行占了四分之一宽度，对话时大多是空的。
3. **每轮都弹通知。** 回合结束弹出“摘要”卡片（分组、智能体名、会话 ID、耗时），几轮下来叠满右下角。
4. **标签过多。** 标题栏有 LOCAL、费用、上下文百分比、带数字的铃铛；输入框下有六个小标签（模型、强度、历史、权限、思考、Enter）；运行时输入框上方再多一条胶囊（智能体名、Thinking、计时、会话 ID、Stop）。窗口标题和侧栏行显示会话 ID。
5. **配色。** 默认 Dracula 紫色，按钮、标签、强调全是紫。
6. **侧栏底部两颗大按钮**（管理智能体、反馈）常驻，顶部是“OFFLINE”。

## 目标观感

以 Claude Code 桌面版为准：安静、以对话为中心、少装饰。不使用 Anthropic 的标志、名称或字体文件。

- **字体：** 界面和对话用系统比例字体，代码、终端、编辑器用等宽字体。
- **配色：** 暖中性色。深色背景接近 `#262624`、侧栏更深，浅色是米白；强调色是陶土橙，只用在主按钮、选中和链接上。跟随系统切换深浅。
- **布局：** 左侧对话列表，中间对话，没有常驻右栏；文件、历史、终端等按需从标题栏打开。
- **对话：** 正文居中、限宽；用户消息是浅色圆角块；助手正文不加框；工具调用是可展开的单行。
- **输入框：** 一个圆角卡片，发送按钮在框内；模型、权限等收进卡片底部的少量菜单。运行时发送按钮变成停止，状态在对话里用一行显示。
- **通知：** 正在看的对话结束时不弹通知；只有后台对话结束、出错或需要处理时才提示。

## 分阶段

1. **基础：字体与配色。**（已完成，见[工作记录](../worklog.md)）新增 Clay 深浅两套主题并设为默认；比例字体作为默认（即现有 Default 预设）；右栏默认收起。已改过主题或字体的用户保持原样。
2. **对话区。**（已完成：摘要通知与回合摘要行；回复操作本来就悬停显示）限宽居中、用户消息样式、工具调用单行化、回复操作悬停才显示、去掉“Worked ! Failed”这类断句；正在看的对话结束时不弹通知。
3. **输入框与标题栏。**（已完成：输入框卡片、发送在框内、安静控件、运行胶囊、窗口标题、标题栏标签；运行时发送键变停止留待后续）输入框卡片化，发送与停止在框内，标签收进菜单；标题栏只留对话名和少量按钮；运行状态移进对话；窗口标题不显示会话 ID。
4. **侧栏与面板。** “新对话”按钮置顶，对话行只显示标题和时间；底部按钮收进菜单；右侧面板改为按需打开；跟随系统深浅色。

每阶段：先补能失败的回归，跑完整单元和 Electron 测试并做反证，深浅两种主题截图核对版面后再开 PR。现有快捷键、命令面板和 CLI 对等不变。
