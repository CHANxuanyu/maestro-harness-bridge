## 用户反馈与问题

2026-10-21 用户确认原始会话接续成功，并对比了同一段对话在 Codex 和 Maestro 中的显示。Maestro 的短回复占用大块卡片空间，模型/思考等级反复出现，时间与时长散落两侧；公开进度、工具组和正文的关系不够清楚。用户需要连续阅读和顺畅接续，而不是围绕每条消息辨认一组仪表信息。

原始对照截图包含私人聊天，只在本地证据中保存；公开问题说明采用文字和后续合成样例。

## 设计方向

1. **正文优先。** 助手回复使用连续文档式阅读布局；短回复按内容高度呈现。限制正文行宽，减少大面积边框、背景和空白。
2. **明确轮次。** 用户输入有轻量而明确的边界；助手正文、公开进度和工具活动属于同一回合，保持原始先后顺序。
3. **状态安静。** 模型、思考等级、时间、时长等移到稳定位置或按需显示，避免每条回复重复抢占正文空间。运行、错误、停止仍应立即可见。
4. **工具可读。** 默认给出紧凑活动摘要，展开可查看真实输入、结果、状态；多次工具与多轮内容不会混淆，长输出可独立滚动。
5. **稳定阅读。** 保留已验证的分页锚点、主动发送跟随、上滚暂停、外部更新不抢位置、资源返回和重启继续。

## 本轮验收标准

- 固定同一组中英文合成会话：一句话回复、长 Markdown、代码块、表格、两次工具、运行中的进度、失败、停止及恢复。
- 对比修改前后相同窗口尺寸的截图，检查一屏可读的有效正文量、行宽、重复信息和操作可发现性。
- 实测流式生成、展开/折叠、滚动与分页、窄窗口和长标题、键盘焦点及屏幕阅读名称。
- 同一原生会话的多轮、工具、停止恢复、重启继续保持通过。不能只用静态截图或发一条消息作为完成依据。

本轮前端由原生 Claude Code Opus 完成；GPT 负责后端、审查和集成。没有修改原生历史来整理截图。极窄窗口的整页头栏裁切、其他提供方完整实机验收和逐字流式刷新精度仍不属于本轮完成声明。

## 第二轮：按回合折叠（2026-10-23）

状态：用户已安装并试用 `1.0.1-hb.4-dev.1`，认可新信息流；按 `v1.0.1-hb.4` 归档发布。开发检查、发布复验和仍未重复的完整接续 GUI 范围见[hb.4 验证记录](../verification/v1.0.1-hb.4.md)。

用户试用 hb.3 后认为信息流仍然难读。对照 Codex 后，主要差距不在间距：上一轮约定「不新增分组」，工具、公开进度和推理只能逐条平铺在正文之间，每条带标签或竖线，一个回合的过程把最终回答挤散。Codex 的做法是回合结束后把过程收进一行「Worked for ...」。

本轮做法：

1. **回合折叠。** `foldTurnActivity()` 以用户消息划分回合，把最终回答之前的工具、公开进度、推理和中途文字收进由首个步骤承载的一行（沿用 `foldNativeToolRuns` 的宿主行方式，原始行 ID、顺序和渲染 ID 映射不变）。回答之后的内容、错误、系统提示与跨智能体回复不折叠。
2. **运行中不折叠。** 标签页忙碌时最后一回合保持展开；没有回答且仍以活动结尾的最后一回合也保持展开，覆盖共享模式下另一端正在生成的情况。
3. **一行工具。** 复用 `describeToolActivity()`，新增 `kind` 供界面本地化动词；补上 Codex `exec`、去掉 `bash -lc` 包装、从补丁头取文件名。
4. **次要样式。** 进展与推理改用次要色，正文标题在对话布局下改为普通粗体。

已知取舍：对话布局里「显示工具调用」开关不再决定折叠，由回合折叠接管；完成后的回合行数减少，未读计数按行计算。真实会话中的长回合、停止恢复、共享模式双向刷新和滚动锚点仍需实机确认。
