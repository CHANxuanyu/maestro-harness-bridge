# 核心体验计划：跨 AI 与关于我

状态：用户已确认方向。2026-10-31 起草。Codex 与 Opus 按下文分工依次实施，无需再等审阅。

## 为什么做这些

产品的核心需求只有两个：

1. **舒服的跨 AI 使用体验。** 用户每天使用 ChatGPT（Codex）、Claude（Claude Code）和 DeepSeek。在 Maestro 里看到同一项目的所有对话，在原生工具里接着做，并且能在一家用完额度或卡住时，顺手换另一家接着做。
2. **Personal agent。** 不管用哪一家，AI 都知道用户是谁、习惯怎样工作。

前五轮已经把六家提供方的原生接续做得很扎实。下一步不再加宽，而是补上这两个需求各自缺的“最后一步”，并先让用户在真实环境中用起来。原则：**不堆复杂度**。每项都复用已有机制，不新增存储体系、提供方或协议。

## 阶段零：发 hb.5，在 Mac 上真实使用一周

- **依据：** hb.4 之后的五轮源码改动全部标为“macOS 未验”。继续在合成测试上叠功能，不如先把现在的主线交给用户日常使用。
- **Codex：** 按[发版规范](../release-policy.md)第 1、2 步准备 `1.0.1-hb.5` 候选 PR：版本号、产品说明、验收文档与已知限制。验收文档列出一张核心流程清单，供用户逐项勾选：
  - 打开 Codex、Claude Code 的项目历史并继续同一会话；
  - 停止后继续，重启应用后继续；
  - 在另一端追加后，Maestro 自动跟随；
  - 在会话浏览器中搜索和预览。
- **用户：** 在 Mac 上执行第 3 步及之后的打包与发布（打包脚本只支持 Apple Silicon macOS），然后日常使用一周。不顺手的地方开 Issue，标签 `dogfood`，作为下一轮的唯一输入。
- **并行：** 下面三项功能可以与试用并行开发，但不进入 hb.5。

## 功能一：DeepSeek 作为第三家

- **依据：** DeepSeek 官方提供兼容 Anthropic 的接口（`https://api.deepseek.com/anthropic`），Claude Code 设置环境变量后即可使用 DeepSeek 模型。Maestro 已支持智能体级环境变量，也已把 `ANTHROPIC_BASE_URL` 识别为网关凭据。所以 DeepSeek 不需要成为新的提供方。
- **做法：** 新建智能体时提供一个“DeepSeek”预设，本质是带以下设置的 Claude Code 智能体：
  - `ANTHROPIC_BASE_URL`、用户填入的 API key、模型名（以实施时官方文档为准，并记录版本和日期）；
  - 独立的 `CLAUDE_CONFIG_DIR`，与真正的 Claude 历史分开，避免两边续接对方的会话出错。
- **显示：** 在会话列表、智能体标签和模型选择中显示为 DeepSeek，不能显示或让用户选择 Claude 的模型名。
- **不做：** 不新增 AgentId，不新增存储适配器。会话仍是 Claude Code 格式，现有读取与跟随直接可用。
- **CLI：** 创建预设智能体的 `maestro-cli` 参数。API key 只从环境变量名或标准输入读取，不出现在命令行参数里。
- **验收：** 预设智能体能新建对话、继续、停止、重启后继续；它的历史只出现在自己的账户下，不出现在 Claude 账户下，反之亦然；界面中不出现 Claude 模型名；API key 在界面中按现有方式遮盖。真实 DeepSeek 账户由用户在 Mac 上验证。

## 功能二：换个 AI 继续

- **依据：** 现在要换一家接着做，路径是：标签菜单，Context: Send to Agent，选智能体，看 token 估算和清理选项，再发送；而且会新建一个“X → Codex”智能体。每换一次就多一个智能体，列表越用越乱。CLI 也没有对应命令（[CLI 与界面对照](../agent-guides/CLI-UI-PARITY.md)已列为缺口）。
- **入口：**
  - 对话的标签菜单和命令面板中的“换个 AI 继续…”；
  - 额度用尽、限流、登录失效的错误提示旁边，这是最常见的时机。
- **选择：** 列出本机可用的另外两家（Codex、Claude Code、已配置的 DeepSeek）。
- **行为：**
  1. 在**同一项目**里，打开目标提供方现有执行者（runner）智能体的新标签；该项目还没有这家时才新建一个。
  2. 新标签的输入框里准备好交接内容：原对话的来源，以及最近几轮的用户消息和回答正文。工具调用每次一行。超过预算时保留最近的部分，并注明省略了多少。
  3. 用户能看到要交出去的内容和大小，可以补一句指示，**按发送才发出**。交接内容成为新原生会话的第一条用户消息。
  4. 原对话不变。
- **复用：** 内容提取复用现有 `extractTabContext` 等上下文转交代码。默认不调用 AI 整理，避免额外的模型调用和等待。
- **CLI：** `maestro-cli` 增加对应命令：指定源标签和目标提供方，返回新智能体与新标签 ID；默认只准备草稿，显式参数才发送。
- **验收：** 三家两两之间都能交接；不新增多余智能体；交接内容与原对话一致且不含工具噪声；未按发送前不会启动任何模型；错误提示旁的入口在对应错误出现时可见；CLI 结果与界面一致。

## 功能三：关于我

- **依据：** “记住我”目前只有 Claude 有（记忆面板仅支持 Claude Code）。每个智能体的 New Session Message 各写各的，换一家，用户的偏好就丢了。
- **做法（用户已选方式 A）：** 设置中增加“关于我”，一份 markdown，写用户是谁、偏好和长期指令。保存后，写进各家原生的全局指令文件中由 Maestro 管理的一段：
  - Claude Code：每个本机 Claude 账户目录（`CLAUDE_CONFIG_DIR` 或 `~/.claude`）下的 `CLAUDE.md`，包括 DeepSeek 预设的独立目录；
  - Codex：`CODEX_HOME` 或 `~/.codex` 下的 `AGENTS.md`。
  - 各家读取这些文件的位置以实施时官方文档为准，并记录出处。
- **规则：**
  - 只改 `<!-- maestro:about-me:start -->` 与 `<!-- maestro:about-me:end -->` 之间的内容，不碰文件其他部分。文件不存在时新建。原子写入。
  - 第一次写入前列出将要修改的文件，由用户确认。之后在设置页显示每个文件的状态：已同步、外部改过、目录不存在。
  - 发现管理段在外部被改过时，先询问再覆盖。清空内容即删除管理段。
  - 这些文件每轮都会加载，显示估算的 token 数（复用记忆面板的估算）。
  - SSH 远程主机不在本轮范围。
- **CLI：** 查看、设置、应用与状态命令，与设置页一致。
- **验收：** 写入前后文件其他内容逐字节不变；Maestro 内外启动原生 CLI 都能读到；外部修改能被发现且不被静默覆盖；删除后管理段消失；跨账户目录都同步。原生 CLI 实际是否加载由用户在 Mac 上验证。

## 冻结

- **Codex 共享连接器：** 只做维护，不再扩展功能或版本适配流程。
- **提供方深度对齐：** 一等公民为 Codex、Claude Code，以及通过 Claude Code 使用的 DeepSeek。其余提供方保持现状，Factory Droid 不再投入。
- **上游功能：** Symphony、Pianola、文档图谱、成就系统等不动，也不在其中加入 fork 的改动。

## 特殊要求

沿用[后端第三阶段的特殊要求](backend-stage3.md#特殊要求)。另外：

1. **外部来源：** DeepSeek 接口、各家全局指令文件位置，只依据官方文档，写明版本与日期。
2. **用户文件：** 写用户的原生配置文件之前必须得到确认；测试只使用临时目录，不碰真实账户目录。
3. **不自动发送：** 任何交接都必须由用户按发送；CLI 需要显式参数才发送。
