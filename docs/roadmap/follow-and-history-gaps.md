Opus 已在 `feed/grok-ui-fixes` 修复[后端第三阶段](backend-stage3.md#交给-opus)交出的 Grok 三项界面问题，处理结果见[提供方契约](../native-provider-contracts.md#grok-的-opus-交接与验收边界)。本轮收尾这些修复的端到端验收，并处理第三阶段留下的其余非界面缺口。任务按顺序进行，每项一个 PR。某项受阻时写明原因，继续下一项。

## 任务一：Grok 自动跟随的完整端到端验收

- **依据：** Grok 已加入 `useNativeTranscriptFollow`。没有原生时间的条目，现在按磁盘顺序与本标签的实时条目一一配对（`mergeNewerEntries`）。e 的消息信息断言已由 Opus 恢复，d 和 f 还没有在启用跟随后重跑。
- **做法：**
  1. 参照 `e2e/native-omp.spec.ts` 的 f，把 Grok 的 f 改成完整界面验收：闲置时外部追加、阅读锚点与未读数、草稿保持、运行中不读、Stop 后刷新。并发写入按 Grok 锁定版本的真实语义写断言；锁定源码没有说明的，记为受阻，不要照搬 OMP 的旁支结论。
  2. 启用跟随后重跑 d，确认重启后续接的新回答只出现一次。
  3. 增加一个场景：外部轮次只写 chat_history、不写 updates。断言工具显示“结果未知”（`data-tool-status="unknown"`），不显示运行中，也不显示完成。
  4. 反证：分别临时回退 hook 的 Grok 条件、`mergeNewerEntries` 的无时间配对、`LogItem` 的无效时间判断，确认 f、d、e 各自在对应断言上失败。临时修改不提交。
- **验收：** 完整 Electron 套件与隔离真实入口烟测通过；反证结果写进记录。

## 任务二：从未打开过历史的标签也能跟随

- **依据：** 对没有原生时间的提供方，标签若全部由本次实时发送组成（新建对话，从未从历史打开），就没有共享的原生 ID 或时间可作锚点。`findNewestSharedEntry` 返回 null，跟随刷新静默失败，外部追加要从项目历史重新打开才能看到。
- **做法：** 只在加载的条目没有原生时间、且没有共享 ID 时，用顺序证据找锚点。例如本标签的用户消息序列与原生用户消息序列逐条对齐，对齐唯一时才采用。重复文字导致多种对齐、或对不齐时，仍返回 null，不猜。有时间的提供方行为不变。
- **测试：** 单元测试覆盖唯一对齐、重复文字造成的歧义、本标签有未落盘的失败发送、外部轮次插在中间。另补端到端：Grok 实时新建对话，外部追加一轮后，新内容只出现一次。

## 任务三：已加载大量历史时的刷新请求量

- **依据：** `refreshNativeConversation` 按 `max(500, tab.logs.length)` 请求历史。性能用例中 5 万条已加载标签每次约返回 20 至 22 MB，最近 500 条约 0.2 MB。真实渲染耗时还没有测过。
- **做法：**
  1. 先测量：IPC 字节数、转换耗时、三个合并函数的耗时，以及一次刷新的总耗时。
  2. 只有测量证明超出预算时才改，例如先读尾部窗口，锚点找不到再按现有逻辑加倍。
  3. 改动后，就地升级（`reconcileTranscriptEntries`）只作用于窗口内的条目。窗口外条目保持原样，写进注释和记录。
- **验收：** 阅读锚点、草稿、未读数和较早消息的内容都不变；给出修改前后的数字。不在后端截断调用者要求的数据。

## 任务四：会话浏览器的账户上下文

- **依据：** [worklog 2026-10-25 交接](../worklog.md#交给-opus会话浏览器的账户上下文)。分页已带所选账户，搜索和查看还没有带。
- **做法：** 给搜索与查看的 preload、IPC 和存储契约补上账户参数，并在 `useAgentSessionsSearch` 和 `useSessionViewer` 里传入，方式与 `useSessionPagination` 相同。界面外观不变。复现用例按交接里写的执行。
- **验收：** 选中自定义账户时，搜索、预览、接续都使用同一账户；所选账户缺失时报错，不回退默认账户。

## 任务五：无效时间的共享兜底

- **依据：** Opus 已在消息信息里处理无效时间，但同类入口仍有问题：
  - 共享的 `formatRelativeTime` 遇到 NaN 时，`Intl.DateTimeFormat.format` 会抛错。`formatTimestamp` 已经有同样的防护。
  - 标签导出给 Grok 消息打印 `Invalid Date`。
  - `computeTabConversationStats` 的时长变成 NaN，最后显示 `0m`。
- **做法：** `formatRelativeTime` 改成与 `formatTimestamp` 一致的不抛错；导出时省略无效时间；时长无法计算时返回 undefined，并让调用者区分“未知”和“0 分钟”。需要新增界面文字的地方先停下，交给 Opus。
