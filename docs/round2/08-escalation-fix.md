# 升级条件的定点修订

2026-11-17。在 PRD v5、原型 P7 的基础上做的定点修订，结果是 PRD v5.1、原型 P7.1。没有重新规划整轮，没有开始正式开发，没有改产品代码，没有提交。你确认的两项是产品方案，不是开工批准。

## 1. 问题是什么

复核的复现：单条对话的升级分支里，"定位"已经找到原因并标为有进展；换做法后出现新问题；再试一次没有进展，就因为"定位、换做法、拆小"各用过一次，宣称授权内办法用完，让你授权另一个模型或自己接手。

**根因不在原型的一个分支，在规则本身。** PRD v5 的 3.1.4 写的是"打法每种对同一个问题只用一次""授权内的打法都用过仍然没有进展，才升级"。同一个限制换着位置出现在：

| 位置                            | v5 的写法                                                                    |
| ------------------------------- | ---------------------------------------------------------------------------- |
| PRD 3.1.4 第 3 至 5 条          | 每种只用一次；没出现预期变化就换下一种还没用过的；都用过才升级               |
| PRD 5.4、5.6 F4                 | "授权内的打法都用过仍无进展"出升级卡片                                       |
| PRD 6.7 第 5 条、"只有这些情况" | 复审不通过且无进展时"必须换一种还没用过的打法"；"授权内的打法都用过"才找老板 |
| PRD 6.8.1                       | 团队"授权内打法都用过仍无进展才升级"                                         |
| PRD R4 表                       | "授权内的打法：每种对同一个问题用一次，都用过仍无进展：升级"                 |
| PRD 6.10                        | "授权内打法都用完仍无进展（团队）"                                           |
| 原型 P7                         | 单聊 f2d、f2x 按这条写死；团队无进展的说明写着"每种打法只用一次"             |
| P7 的检查                       | 只核对升级卡片上的字和按钮，没有核对此时该不该升级                           |

检查能全过，正是因为它验证的是"卡片写了什么"，而不是"此时应不应该出卡片"。

**顺带查出的同类问题，一并改了**：PM 的模型不可用、没有替补也没授权临时接任时，v5 会直接来问你。可等原来的模型恢复本身是一条授权内的正常等待（3.1.3）。现在：不设截止时间，或恢复早于截止时，团队自己等，其间做不需要 PM 的事；只有等恢复会错过截止时间时，剩下的两条路（临时接任要新权限，等恢复要追加时间）都越过边界，才问你。见 PRD 6.8.2 接任顺序第 3、4 条，R3 第 7 条，T21。

**保持不变**：两次打回后内部复盘；未满足已确认标准就不能进入演示和正常交付；违反已确认标准的问题不能叫"小毛病"放行；三种终态如实记录。

## 4. 原型怎么改的

**一个判断函数，三处共用。** 原型里新增 `judgeAttempts()`（判定每次尝试：第一次、有进展的四种、无进展、回到旧报错、重复）和 `decideNext()`（决定下一步：继续、诊断、补证据、升级、写未完成报告）。它只读应用能观察到的东西：实际改动的标识、做完后还失败什么、新拿到的证据。类别和措辞只用于显示，函数里没有任何地方读类别。单条对话、团队的问题 #1、PM 评审都由它决定下一步，界面上的尝试记录和卡片从它的结果画出来。

**单条对话（跟进与验收）**

| 步                                         | 发生了什么                                                                   | 判断                                                                                                 |
| ------------------------------------------ | ---------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 第 1 至 3 次                               | 补导入、换导入路径；第 3 次助手说"换一种写法"，应用比对实际改动和第 1 次相同 | 第一次、无进展、重复；三次无进展，先诊断                                                             |
| 诊断后第 4、5 次                           | 定位到改名记录；改调用处后旧报错消失，冒出新问题 TS2300                      | 新证据、失败变了；问题状态"部分解决"；继续                                                           |
| 第 6、7 次                                 | 又一次定位（新报错、另一个假设）；小实验得出"不能整包排除"                   | 都是新证据；定位、换做法、小实验都已用过，但授权内还有有依据的下一步，继续；"换更强的模型"只列为建议 |
| 第 8 次（默认）                            | 小实验：只覆盖冲突的那一条声明                                               | 已解决，检查 2/2，全程没有卡片                                                                       |
| 第 8、9 次（点"模拟：剩下的路需要你登录"） | 覆盖盖不住全局声明，查到 2.3 删除了它；安装 2.3 时私有源返回 401             | 授权内没有有依据的下一步，剩下的路要本人登录或放宽检查：升级                                         |

升级卡片写明：卡在哪（安装要登录私有源，401）；授权内每条路的结论（第 7、8 次、重装只会重复第 9 次、skipLibCheck 属于放宽）；不推荐换模型的理由（卡住的是登录不是能力）；预算（已用 36 分钟，总时限 2 小时）。选项是"我来登录"（推荐）、"批准打开 skipLibCheck"（会记为标准变更）、"先停在这里"，没有"继续"，也没有"换模型"。

**团队**：问题 #1 的三次修复判为无进展，PM 主持复盘；之后 QA 定位、开发连做两次小实验，第一次只解决一半也算有进展，接着做，第二次解决。PM 评审记录用同一套判定：第 2 次评审有进展但连续两次打回，照样复盘；复盘后第 3 次有进展，继续修；第 4 次通过才演示。PM 模型不可用时按截止时间决定是自己等还是问你。

**每张要你操作的卡片都带一个边界属性**（预算、改变承诺、新权限、新模型、本人登录、确认基线、演示验收），检查就是按这个属性核对的。

## 7. 剩余已知问题

**规划缺口（原型和 PRD 还没覆盖的）**

- 团队里因"本人登录"而升级没有画，只在单条对话里画了；团队的另外三种边界（预算、改变承诺、新权限）画了。
- "授权内暂时想不出有依据的下一步，先补证据"（3.1.4 第 6 条）原型里没有单独一步，只在判断函数的检查里覆盖。
- 重复判定的比对方式只定了原则（先按改动内容和失败签名严格比对，宁可漏判），"内容相近但不完全相同"怎么算，要在开发阶段定细节（PRD 第 10 节第 5 条）。
- 上一轮留下的：暂停与继续、PM 漏报和格式错误等四种故障状态、收尾计划没有画；窄窗口、读屏、对比度没有检查。

**开发阶段待验收（原型代替不了的）**

- 真实模型会不会照规则写依据、区别和预期，诊断能不能给出有新依据的方案（T11、T23）。
