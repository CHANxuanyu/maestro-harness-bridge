# 原生接续端到端验收

这套用例运行仓库的 Electron 开发构建，覆盖多轮、工具结果、Stop、重启、原生历史、跨应用刷新、共享线程、摘要隔离、窄窗口和输入焦点。它不构建或安装发行包。实施与反证记录见[计划书](../roadmap/native-e2e.md#完成记录)。

## 在 Mac 上运行真实模式

在已经准备好仓库依赖的工作目录中，确认本机已有登录成功的 Claude Code `2.1.310` 和 Codex CLI `0.163.0-alpha.11.1`，然后运行：

```sh
MAESTRO_E2E_REAL=1 npm run test:e2e
```

命令只构建 main、renderer、cli 并启动测试，不下载 CLI、不安装、不打包、不发布。版本不匹配或登录不可用时直接失败，不切换账户或退回假程序。默认通过 PATH 查找 CLI；需要指定已有可执行文件时，设置 `MAESTRO_E2E_CLAUDE_PATH` 和 `MAESTRO_E2E_CODEX_PATH`。Node 需满足仓库现有要求。

先做多轮与重启的短验收可以运行：

```sh
MAESTRO_E2E_REAL=1 npm run test:e2e -- --grep ' a:| d:'
```

短验收是 4 条用例、8 个原生回合。完整非共享验收是 21 条用例，包含失败清理自检，约启动 36 个原生回合或摘要调用；显式加入共享模式后共 25 条用例，再增加约 9 个回合。工具续接可能使一个回合包含多次模型请求，实际额度或费用取决于账户、模型、上下文和工具行为，不能按这个回合数当作固定账单。除了摘要场景外关闭测试会话的历史摘要，避免无关消耗。所有模式自动重试均为 0。

## 账户和会话隔离

每条用例都创建全新的项目、Maestro 数据目录、`CLAUDE_CONFIG_DIR` 和 `CODEX_HOME`。测试不导入已有会话，不接受临时目录之外的续接 ID，也不复制账户配置、hooks、数据库或项目历史。

- Codex 只将所选 `CODEX_HOME` 下的 `auth.json` 复制到临时目录，权限为 `0600`；未指定时从默认 Codex 账户目录读取。原生 CLI 对副本的写入不写回源文件。仅存在于系统凭据库、没有这个文件的登录方式未支持，启动时会明确失败。
- Claude 优先沿用明确设置的 `CLAUDE_CODE_OAUTH_TOKEN` 或 `ANTHROPIC_API_KEY`。否则只读所选 `CLAUDE_CONFIG_DIR` 的 `.credentials.json`；默认 macOS 账户还可只读系统钥匙串的 `Claude Code-credentials`。只取访问令牌，不复制刷新令牌，不改写钥匙串。令牌过期时应在验收外完成正常登录刷新，再重新运行。
- 实际 CLI 仍会访问服务端并消耗所选账户额度。隔离的是本地文件和测试会话，不是新的服务端账户。认证失败、限额和原生写锁拒绝会原样导致验收失败。

用例只给真实 CLI 普通工作指令，要求在临时项目执行指定命令；不改写它的 stream-json、事件或转录。摘要场景在原生子进程结束后暂缓转发退出，用来记录摘要开始前的文件字节。这个门只在测试启动器内，产品没有测试参数或旁路。

## 可选的共享模式

只有明确提供已安装的连接器路径才运行共享场景：

```sh
MAESTRO_E2E_SHARED_PATH=/absolute/path/to/codex-shared.py MAESTRO_E2E_REAL=1 npm run test:e2e
```

连接器及其对应原生运行时须已按现有流程安装并验证。先正常退出 ChatGPT 桌面应用，因为现有连接器的空闲停止管理会检查它；测试不替你关闭应用。测试使用独立 `MAESTRO_SHARED_STATE`、新建线程和真实连接器的检查、启动、验证及空闲停止命令，不修改原生身份检查、写锁或安装路径。

共享忙碌和队列场景只操作自己新建的线程；先让真实命令等待，再添加队列并中断，保留暂停的队列进行拒绝验收。清理时只删除该测试线程的队列并停止自己的回合和运行时。临时共享运行时使用锁定官方测试同样的 `features.default_mode_request_user_input=true` 开关，让默认模式可以请求用户确认；不更改产品设置。确认提示场景必须收到实际服务端确认请求；模型没有发出请求、当前原生策略不允许请求或接口拒绝时，用例失败，不合成一条确认事件冒充成功。

未提供路径时，共享场景不纳入本次真实模式选择，摘要明确记为未验。CI 的确定性模式始终运行共享场景。

## 输出与清理

Mac 的每条用例使用 `/tmp/maestro-native-e2e-*`，Linux 使用系统临时目录。每条结束后清理自己的应用、CLI 子进程和临时目录，包括失败路径；共享服务也在自己的清理路径中关闭。机器断电或强制杀死整个测试进程可能来不及清理，此时先确认对应测试进程已退出，再只删除本次遗留的那个临时目录，不删除真实账户目录。

本地保留的输出在仓库忽略目录中：

| 路径                              | 内容与处理                                                                                                                                  |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| `e2e-results/native-summary.json` | 场景字母、提供方、状态、CLI 版本、应用提交、工作区是否有改动、平台与共享选择。无提示词、回答、原生 ID、账户路径或错误正文，可用于验收记录。 |
| `e2e-results/` 其他文件           | 失败截图、trace 和共享原生诊断日志，仅本地排查，不入库，不作为公开证据。                                                                    |
| `playwright-report/`              | 本地 HTML 报告，可能含诊断内容，不入库。                                                                                                    |

正常结束后可直接删除这两个报告目录。摘要中的 `applicationCommit` 对应开发构建的源码，`sourceDirty: true` 表示还包含未提交改动，不能据此宣称验证了纯净发行包。`syntheticCredentials: true` 表示 Linux 合成冒烟，不能作为真实账户验收。

## 云端验收与限制

```sh
npm run test:e2e:fixtures
npm run test:e2e
npm run test:e2e:real-smoke
```

最后一条用假程序充当已安装 CLI，并且只生成合成凭据。它走真实模式的凭据隔离、普通及共享启动、相同断言、退出和清理路径，核对源凭据逐字节不变、源目录未增加文件、运行目录已清空。CI 保留 `forbidOnly`，不开重试；真实账户模式不在 CI 运行。

真实模型可能产生额外说明、拒绝命令、没有并行执行或没有发出确认请求，这些都不会被测试适配器修饰成预期输出。f 场景还会在自己的新会话中尝试外部写入，原生 CLI 若因并发写锁拒绝，验收如实失败，不解释为支持同时写入。Claude 摘要若遇到残留 thinking 空壳被 API 拒绝，按现有 `Synopsis failed` 路径失败，不重试或改成本地摘要；下一次正常 API 回合清理后不再有该空壳问题。

Linux 合成用例通过只证明云端开发构建及测试基础设施的结果。macOS 字体布局、真实账户、真实模型行为、系统钥匙串读取和桌面原生 socket 身份仍未验，需使用上面的命令在 Mac 上补验。新发现的界面问题保留场景名、操作和可公开的复现描述交给 Opus，不在本任务修改前端行为。
