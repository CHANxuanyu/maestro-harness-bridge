## Windows CI 发现的问题与修复

首次远端 [CI 39633038452](https://github.com/CHANxuanyu/maestro-harness-bridge/actions/runs/39633038452) 的静态检查和 Linux 两个分片通过，Windows 共失败三项。失败结果保留，不记为全绿：

- `codex-session-storage-messages.test.ts` 的本地索引文件断言使用本机路径分隔符；读取的账户与文件身份不变。
- `project-history.test.ts` 的本地项目路径断言采用本机绝对路径规则；最具体项目与 owner 归属断言保留。
- `shortcuts.test.ts` 的真实源码扫描兼容 LF 和 CRLF；显式验证两种换行解析出相同翻译键，并保留非空、翻译存在、Git 前缀及两个创建 PR 分支的断言。此项由原生 Claude Code Opus 完成，GPT 修复两项后端测试。

三份测试在本机的针对性回归为 **67 通过、0 失败**，格式与 ESLint 通过。测试用例没有被跳过或删除。

## 最终发布核验方式

本版本必须在 Linux、Windows 的完整 CI 及静态检查成功后发布。各平台实际数量与检查提交见 Release 附件 `VERIFICATION.json` 和其中的 GitHub run 链接；平台跳过项不同，不累加重复测试，也不把 Windows 单元测试通过写成 Windows GUI 或二进制验收。

应用从明确提交完整构建，写入版本与 commit，重新打包 macOS arm64 ZIP。`BUILD-MANIFEST.json` 记录源码提交、逐文件核对数量、asar 与 ZIP 身份、原生模块烟雾测试、签名和公证状态；`SHA256SUMS.txt` 用于核对下载。Release 标签、实际构建 commit 与资产对应关系必须由记录核实，旧候选包的校验值不得挪用到新包。

原始实机验收应用和发布重构建包分别标识。发布构建验证不会读取私人会话、启动 agent 或自动替换现有应用；没有重复原始会话 GUI 流程的记录就不宣称重新测过。

本版仅发布 macOS Apple Silicon 预览，临时签名，未经 Apple Developer ID 公证。停止的子进程即时终止延迟未测量；其他系统和提供方的完整 GUI 流程未等同验证。信息流阅读区仍待改造，见 [Issue #1](https://github.com/CHANxuanyu/maestro-harness-bridge/issues/1)。
