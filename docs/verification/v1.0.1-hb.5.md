## 云端与实机的边界

合并前要求 `HB release policy`、`lint-and-format`、Linux 两个测试分片、Windows 两个测试分片，以及 `Native resume E2E (Linux)` 全部通过；合并后再次确认该源码提交的 push CI。没有跳过任务、降低断言或用空提交重跑。自动检查的实际链接由阶段零 PR 保留，完成记录见计划书末尾。

Linux 合成端到端使用临时项目、数据目录、假程序和合成凭据；不会访问用户真实会话或账号目录。原生模式的版本及隔离方式见[端到端说明](native-e2e.md)。Mac 真实账户、桌面 Codex、GUI、应用包、签名和 SQLite/PTY 实际运行均待用户执行。核心流程清单的勾选必须来自本次 hb.5 包，不沿用 hb.3/hb.4 的观察。

## Mac 操作顺序

以下只供用户执行。本轮云端不运行打包、安装、标签或发布操作。命令在该仓库根目录运行，Mac 已有 Node.js 22 或更新版本、Git、GitHub CLI 及已登录的锁定原生 CLI。使用自己的干净 checkout，不覆盖未提交改动。

### 1. 冻结阶段零合并提交并复核 CI

```sh
HB5_REPO=CHANxuanyu/maestro-harness-bridge
HB5_SOURCE=$(gh pr list --repo "$HB5_REPO" --state merged \
  --head codex/core-experience-hb5-candidate --base codex/i18n-zh-cn \
  --json mergeCommit --jq '.[0].mergeCommit.oid')
test "${#HB5_SOURCE}" -eq 40
test -z "$(git status --porcelain)"
git -c credential.helper= fetch https://github.com/CHANxuanyu/maestro-harness-bridge.git "$HB5_SOURCE"
git switch --detach "$HB5_SOURCE"
test "$(git rev-parse HEAD)" = "$HB5_SOURCE"
gh run list --repo "$HB5_REPO" --commit "$HB5_SOURCE" --event push \
  --workflow ci.yml --json databaseId,headSha,status,conclusion,url
```

从输出取该提交的 CI run ID，核对七个 job 均为 `success`、不是 skipped，记录链接和 ID。未完成或失败就停在这里，不引用更晚主线的通过结果。

```sh
HB5_CI_RUN='<上一步实际通过的 run ID>'
gh run view "$HB5_CI_RUN" --repo "$HB5_REPO" --json headSha,status,conclusion,jobs,url
npm ci
npm run release:hb:check
npm run lint
npm run lint:eslint
npm run format:check:all
npm run lint:doc-refs
npm run test
npm run test:release-policy
npm run test:codex-shared
npm run test:e2e:fixtures
npm run test:e2e
MAESTRO_E2E_REAL=1 npm run test:e2e -- --grep '(claude|codex) '
```

这里明确选择核心清单的 Claude/Codex 场景；不加筛选会要求另外四家提供方也已安装并登录。真实模式会消费已选账户的额度，使用临时账户副本和新会话。共享模式及显式 CLI 路径按[端到端说明](native-e2e.md)设置；未跑共享的结果不能填成共享通过。桌面更新后先执行 `python3 scripts/codex-shared/check-version.py`，未知版本不得绕过或冒充已准入版本。

### 2. 构建并核对发行包

```sh
test -z "$(git status --porcelain)"
npm run package:harness-bridge:mac
npm run package:codex-shared
HB5_APP="$PWD/release/harness-bridge/mac-arm64/Maestro I18n.app"
codesign --verify --deep --strict --verbose=2 "$HB5_APP"
unzip -t release/harness-bridge/Maestro-I18n-1.0.1-hb.5-mac-arm64.zip
unzip -t release/codex-shared/Maestro-Codex-Shared-1.0.1-hb.5.zip
/usr/libexec/PlistBuddy -c 'Print :CFBundleShortVersionString' "$HB5_APP/Contents/Info.plist"
/usr/libexec/PlistBuddy -c 'Print :CFBundleIdentifier' "$HB5_APP/Contents/Info.plist"
```

核对内嵌 `package.json` 为 `1.0.1-hb.5`、入口与构建文件齐全、界面构建 commit 与冻结来源相符。临时签名不等于 Apple 公证。对包内 arm64 SQLite 实际查询 `SELECT 42`，对包内 node-pty 实际执行短命令并核对输出和正常退出；不要用构建机 Node 的测试替代包内模块。随后按上面的清单运行本次应用包，并扫描源码、新增凭据及包内容，记录真实结果。构建脚本只生成产物，不会自动安装或完成这些实测。

### 3. 整理五项资产，验证后创建标签与草稿

```sh
HB5_ASSETS=$(mktemp -d "${TMPDIR:-/tmp}/maestro-hb5-release.XXXXXX")
cp release/harness-bridge/Maestro-I18n-1.0.1-hb.5-mac-arm64.zip "$HB5_ASSETS/"
cp release/codex-shared/Maestro-Codex-Shared-1.0.1-hb.5.zip "$HB5_ASSETS/"
```

在该目录填写 `BUILD-MANIFEST.json` 和 `VERIFICATION.json`，按[证据最低内容](../release-policy.md#证据的最低内容)与 hb.4 公开附件结构记录本次实际字节、版本、完整来源、Mac 测试、真实主线 CI run ID、隐私检查和 GUI 范围。新 GUI 字段为 `gui.fullOriginalCrossAppWriteSequenceRepeated`。未验项保持 false 并列入 limits；未做包内 SQLite/PTY 或隐私检查时不能填成通过。不要复制旧附件的数值，不把测试样例当成发行证据。

```sh
(
  cd "$HB5_ASSETS"
  shasum -a 256 Maestro-I18n-1.0.1-hb.5-mac-arm64.zip \
    Maestro-Codex-Shared-1.0.1-hb.5.zip BUILD-MANIFEST.json VERIFICATION.json > SHA256SUMS.txt
)
node scripts/hb-release.mjs assets --dir "$HB5_ASSETS"
git ls-remote --tags https://github.com/CHANxuanyu/maestro-harness-bridge.git 'refs/tags/v1.0.1-hb.5*'
gh release view v1.0.1-hb.5 --repo "$HB5_REPO"
```

确认远端没有该标签和 Release 才执行下一段。若已经存在，按发布制度核对其 ID 和来源后恢复同一候选，不能覆盖上传或移动标签。将说明文件复制到私有发布记录目录，按实测结果改掉“尚未打包或发布”的候选状态，保留全部限制。

```sh
HB5_NOTES='<本次实际发布说明的绝对路径>'
git tag -a v1.0.1-hb.5 "$HB5_SOURCE" -m 'Maestro Harness Bridge 1.0.1-hb.5'
git push https://github.com/CHANxuanyu/maestro-harness-bridge.git refs/tags/v1.0.1-hb.5
gh release create v1.0.1-hb.5 --repo "$HB5_REPO" --verify-tag \
  --draft --prerelease --latest=false --title 'v1.0.1-hb.5' --notes-file "$HB5_NOTES" \
  "$HB5_ASSETS/Maestro-I18n-1.0.1-hb.5-mac-arm64.zip" \
  "$HB5_ASSETS/Maestro-Codex-Shared-1.0.1-hb.5.zip" \
  "$HB5_ASSETS/BUILD-MANIFEST.json" "$HB5_ASSETS/VERIFICATION.json" "$HB5_ASSETS/SHA256SUMS.txt"
npm run release:hb:verify -- --tag v1.0.1-hb.5 --dir "$HB5_ASSETS" --notes "$HB5_NOTES" --state draft
```

### 4. 发布、匿名下载复核与一周试用

```sh
gh release edit v1.0.1-hb.5 --repo "$HB5_REPO" --draft=false --prerelease --latest=false --verify-tag
npm run release:hb:verify -- --tag v1.0.1-hb.5 --state published
curl -fL https://github.com/CHANxuanyu/maestro-harness-bridge/releases/download/v1.0.1-hb.5/SHA256SUMS.txt
```

再用未登录浏览器下载两个 ZIP，核对与清单一致；确认发布后的 `Verify HB release` 工作流通过。正常退出旧版并备份配置后替换应用，按[启动与回退说明](../release-notes/v1.0.1-hb.5.md#下载升级与启动)使用。一周内的问题统一用 `dogfood` Issue 留下操作、预期与实际结果，作为下一轮输入。
