## 交给 Opus 的界面复现

本轮未启动 GUI，没有新增已实见的界面问题。以下来自[核心体验完成记录](../roadmap/core-experience.md#完成记录)、[接口契约](../core-experience-contracts.md)及[前置项](hb6-prerequisites.md)，在 hb.6 包复验，界面、文案和外观继续由 Opus 处理。

1. **DeepSeek 遗留历史：** 用专用测试智能体产生一轮后删除该智能体，从项目历史重开。核对是否建成缺少网关配置的普通 Claude 执行者；在确认路由前不发送。应保持可辨认的 DeepSeek 身份与正确账户，不能默默用 Claude 接着发。
2. **Codex 交接预览：** 发送一份交接草稿，在会话浏览器预览其首轮，再正常打开对话。对比预览是否多出 Maestro 系统封装；应一致呈现用户正文，保留原生文件。
3. **未发送草稿：** 准备交接但不发送，切到别的对话后回到侧栏。检查草稿是否仍只能看成“新建对话”，用户能否辨认并找回它；新增标识由 Opus 决定。
4. **向导提示：** 同步关于我后分别新建向导和 `/wizard`，对比普通对话的提示。向导仍带全文属于已知未完成项，不能把普通对话去重表述为所有入口都去重。
5. **Codex 输出与拒绝：** 普通 exec 执行长命令应持续显示运行状态，完成后展示完整输出；共享模式另验输出跟随与上滚。原生 effort 为 null 时显示未记录，显式 high 时显示 high。另一端结束后立即续接，若收到 active writer 拒绝，应保留输入并明确失败，不假报恢复、不删锁、不重试。
6. **多窗口退出：** 按上表同时改变两个窗口尾部，再验正常退出、更新退出和无响应窗口；已有单个副窗口场景不能替代这三个检查。记录每个窗口实际保存情况，不自行修改前端。

## Mac 后续顺序

1. Opus 从全新克隆复核候选内容，完成审查合并与七项检查；合并后核对实际源码提交的 push CI。这个无远端的本地分支不执行这些动作。
2. 用户在验收外重新登录 Claude，提供自己选择的可用账户；Opus 先展示真实模式命令和范围，再按上文记录实际结果。不放宽断言、不跳过应验项、不加重试。
3. 依发布制度冻结干净源码，在 Apple Silicon Mac 构建应用及连接器。验 ZIP、签名、内嵌版本和 commit，实跑包内 SQLite 与 PTY，完成源码与包隐私扫描。临时签名不等于 Apple 公证。
4. 用户在本次发行包逐项勾选核心流程、三项功能及改版检查；Opus 完成剩余界面复现。真实模式与发行包 GUI 的结果分别填写，未验项继续保留限制。
5. 用实际字节形成五项资产并通过 assets 检查，再按发布制度核对编号、创建注解标签、上传草稿、验证和公开；每一步先给用户看命令。本轮没有标签、草稿、安装包或五项资产。
