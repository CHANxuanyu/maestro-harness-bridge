# 原生命令第三轮验收

只用临时目录和合成提供方，不读取个人账户，不调用模型。外部 Electron 验收在首次命令可见性断言失败，trace 已有命令、来源和描述，问题是命令名与来源缺少文本分隔。第三轮修复已通过单元回归，修复后的 Electron 场景尚未运行。

## 自动场景

在沙箱外运行，入口会依次构建主进程、桌面渲染器、网页包和 CLI：

```sh
MAESTRO_E2E_REAL=0 npm run test:e2e -- e2e/native-commands.spec.ts --retries=0
```

该场景覆盖新增命令后重新打开列表、项目覆盖用户、CLI 查询、扫描期间重复按发送和继续写草稿、项目正文与参数进入合成转录、原生初始化报告的插件命令在界面和 CLI 都可见，以及换账户后旧插件消失。合成提供方只写临时目录；场景开始的发现检查不启动回合，后段只运行仓库内的假提供方。

保留原来的完整按钮名称、来源、正文和单回合断言。延迟扫描通过主进程临时阻塞该账户命令目录的 `stat` 实现，使用 `expect.poll` 确认扫描已进入，再继续草稿操作；`finally` 释放读取并恢复方法。不要改写 `contextBridge` 暴露的只读方法。此处没有新建标签后的立即 CLI 读取；`NativeApp.cli` 已自动添加 `--json`，按返回对象断言。

## 额外 Electron 和 SSH 场景

1. 在临时 Codex 账户中放入一个提示词文件，开启新界面。让一条合成回合保持忙碌，提交该命令入队。在出队时令发现 IPC 返回 `remote-unavailable` 或拒绝 Promise。断言没有新进程启动，队列仍含原项目、原标签和原命令，条目处于暂停状态。恢复发现后，用队列现有的强制发送按钮发送一次，确认仅启动一次。CLI `queue list` 应能读到保留项；按条目强制发送没有 CLI 等价动作，已记入 Open gaps。
2. 在专用 SSH 测试主机上建立临时账户目录，将其 `commands` 和 `skills` 指向同主机上可读的临时共享目录。打开 `/` 并通过 `tab commands` 检查两者均可见。在目标目录新增文件，重新打开列表应刷新。模拟断网或拒绝读取后，只剩内置命令和本地化说明。恢复连接后重新发现，不能读本机同名目录。
3. 使用带同名个人和项目技能的合成 fixture，验证 UI 普通发送和空闲时 CLI `dispatch` 都传入项目正文。真实 Claude 的技能 frontmatter、相对附件、动态 shell 插值和索引参数语义不在本轮覆盖范围，不能把正文验证等同于原生技能完整等价。
4. 在新界面关闭后复测既有 `agentCommands` 展示和原生裸命令发送，确认旧界面不采用文件扫描的项目正文展开。

真实 SSH 场景要求外部测试主机，本轮仅写出步骤，未建立连接。真实工具和模型验收不包含在本任务授权中。
