# 新界面文案验收

U6 的源码和组件回归已在沙箱内执行。以下 Electron 场景留给 Opus 在沙箱外执行，本轮没有运行它们，也没有测试安装包。

## 自动场景

在本任务分支执行：

```sh
MAESTRO_E2E_REAL=0 npm run test:e2e -- e2e/native-new-shell-copy.spec.ts --retries=0
```

该命令构建 main、renderer、CLI，然后运行唯一指定的场景。不要使用真实账户模式。场景使用 `NativeApp` 的临时数据目录，并把 Electron 和 CLI 的 HOME 指向临时目录；不创建工具实例、不发送消息、不调用模型、不安装 CLI。

验收内容：

1. 首次打开英文新界面时，更新偏好弹窗标题为 `Update preferences`，测试版没有推荐标记，崩溃报告明确重启后生效。
2. 通过现有 `settings set uiLanguage zh-CN` 切换到中文，弹窗即时更新为自然中文，三个已保存的 false 值都不变。
3. 通过现有 `settings set newShell false` 切回旧界面，旧标题和推荐标记保持原样。
4. 切回新界面后点击测试版开关，确认仍写入同一设置；再次点击恢复 false，继续后只标记该步骤已完成。

## 需人工核对的呈现

在隔离的临时项目中，以合成对话、工具事件、文件及错误数据检查下列项目。不要复用真实账户目录，不发送消息，不执行恢复或登录命令。

| 表面       | 核对内容                                                                                       |
| ---------- | ---------------------------------------------------------------------------------------------- |
| 左栏与顶栏 | 项目、对话、新建入口、历史读取失败、菜单与悬浮提示；英文和中文均没有旧层级称呼                 |
| 输入区     | 空状态、提及路由、权限说明、交接草稿和令牌提示；只检查展示，不发送                             |
| 改动与任务 | 空状态、加载、错误、合成差异与任务条目；路径、代码及任务原文不被翻译                           |
| 文件与预览 | 新建、重命名、删除、冲突、失败反馈、SSH 不支持提示、预览模式菜单、图片及媒体错误；使用临时文件 |
| 终端       | 搜索、无匹配、右键选区与链接菜单、触屏方向键、启动失败和退出码；保留原始终端输出               |
| 错误与确认 | 合成错误标题、恢复按钮、额度说明、toast、退出确认；展开详情时原始错误逐字保留                  |

窗口缩窄后检查中文按钮是否截断，长路径和原始错误是否挤压操作区。在 en 与 zh-CN 下分别检查，再将 `newShell` 关闭核对旧界面文案。截图、trace 和实机结论只写到私有验收目录，不加入公共提交。

## 扫描边界

测试内的 `scanNewShellCopy.mjs` 按表面列出 JSX 文案与文件操作反馈，理解直接的 `newShell` 条件分支。它不解析运行时变量、动态 key、任意函数调用或完整组件可达性，因此扫描通过不能代替 Electron 验收。

保留的扫描项是品牌或协议名（DeepSeek、GIT、jq）、键名和快捷键、倍速单位 x，以及新界面已隐藏的 Auto Run 和 Document Graph 菜单。文件菜单回归单独验证后两项在新界面不可见。用户内容、路径、文件名、命令、模型输出和供应商诊断保持原文。
