# 新界面权限第二轮验收

本轮只准备场景，没有运行 Electron。全部使用临时项目、临时应用数据和合成提供方，不使用个人账户或真实模型。

## 可执行 Electron 场景

在本克隆执行：

```sh
MAESTRO_E2E_REAL=0 npm run test:e2e -- e2e/native-new-shell.spec.ts --grep 'permission review' --retries=0
```

该命令先重建 main、renderer、CLI，再运行四条新增场景：

1. 标准权限的空 Claude 对话关闭后，经 `update-agent --provider codex --force` 换工具，用恢复快捷键找回带名称标记的原对话。核对权限、原生 ID 为空，以及一次合成发送的 Codex 参数确实是只读沙箱，没有完全访问参数。
2. 桌面来源仍为完全访问，通过真实 `web.requestNewTab` 预加载接口传入浏览器只读来源。核对返回值、桌面权限控件和来源未被改写。这条覆盖 Electron 的实际回调链，不等同于真实浏览器点击验收。
3. 两个窗口初始都是完全访问，在第二窗口改为只读。仅拦截发往第二窗口的权限快照查询，制造真实 250 毫秒无答复，保留第一窗口的完全访问答复。CLI 新建应为只读。
4. 两个未分组来源初始属于项目 P。在窗口 A 收紧权限，在窗口 B 把目录改到临时项目 Q 并使用完全访问对话。核对 B 的实时快照已属于 Q，再通过 CLI 为 A 新建，结果必须只读。

同时可复跑原来的两条权限继承场景：

```sh
MAESTRO_E2E_REAL=0 npm run test:e2e -- e2e/native-new-shell.spec.ts --grep 'permission inheritance' --retries=0
```

失败应保留首次结果和临时夹具证据，不自动重试。

## 真实浏览器补充场景

这是尚未自动执行的人工验收步骤，不能用上面的第二条替代。先构建 `npm run build:web-desktop`，在临时数据的 Electron 实例里启用浏览器访问并完成该实例的登录。使用临时提供方配置，所有步骤都只创建空对话，不发送。

1. `newShell=true`，桌面当前对话为完全访问。浏览器打开同一对话，将权限改成只读；确认桌面副本仍为完全访问。
2. 在浏览器点击该对话的“新会话”，核对请求携带相同来源标签 ID 和 `sourcePermissionMode: readonly`。返回字段、浏览器控件和桌面新对话均应为只读。
3. 反向检查：桌面为只读，浏览器为完全访问。新对话仍为只读。Claude 标准权限与完全访问组合取标准权限，标准权限转到 Codex 时取只读。
4. 保留一个较新的完全访问后台对话，重复第一步，确认显式来源没有被后台对话代替。来源对话的权限不得被创建动作改写。
5. 在第二窗口将来源移到另一 SSH 主机，保持相同项目分组。快照的主机值必须改变，新对话不能继承另一主机的完全访问。只检查配置和空对话，不连接 SSH 或发送内容。
6. `newShell=false` 时，重复旧界面的创建与恢复动作，行为应与本轮修复前相同。

跨窗口旧副本的精确输入由 Vitest 回归控制。Electron 场景验证真实窗口路由、超时和目录更新，不能单独证明任意时刻的并发排序或实际浏览器控件已验收。
