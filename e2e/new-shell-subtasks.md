# U3 子任务验收

本轮只运行了单元测试、类型检查和 Playwright 场景收集，没有启动 Electron。
以下由 Opus 在沙箱外执行，使用本克隆源码重新构建；不复用日常用户配置。

```sh
npm run build
MAESTRO_E2E_REAL=0 npx playwright test e2e/native-subtasks.spec.ts --project=native --retries=0
```

自动场景使用 `NativeApp` 的临时目录和合成 Claude / Codex 协议夹具。
若误开真实模型模式，场景会报错，不读取真实凭据、不跳过测试。

自动场景检查：

1. 父对话先取得原生 ID，随后通过 @提及派出子任务。左栏自动展开，显示 Codex 标记和运行状态，标题只取第一句，无未读标记。
2. 点开仍在运行的子任务，输入补充要求。先进入同一标签的队列，咨询完成后继续，原生文件仍只有一份。
3. 带调用方身份的 `dispatch --new-tab` 生成同一父对话下的另一子任务；`tab children` 能读回两个子对话。
4. 关闭来源标签，子任务挂到原生历史父行下；正常重启后仍能点开并继续。

另需人工检查，不能记作上述自动场景覆盖：

1. 中英文各看一次默认折叠、运行自动展开、运行时手动收起、下一次运行再展开，以及嵌套子任务的键盘导航和菜单。
2. 失败、取消以及进程异常退出后的状态。插话只能在前一轮结束后执行，错误信息应可见。
3. 同目录不同账户、同名目录不同 SSH 主机、worktree 来源关闭后的归属。远程未做实际连接验证。
4. 关闭新界面开关，确认原有咨询无 chip、无未读；切换前正在运行的子任务结束后不能卡在忙碌。
5. 多窗口分别持有父对话和目标对话。目前派发来源通知仍只发给调用方窗口，另一窗口拥有的子对话来源写入尚未保证，应记录为限制，不当作已通过。

已有历史咨询若从未记录父原生 ID，原父标签关闭后无法补猜身份。
CLI `tab children` 以仍打开的父标签为入口，父标签关闭后须先从界面重新打开历史行再查询。
展开和收起是当前界面的本地状态，CLI 只读取子任务，不修改折叠状态。
