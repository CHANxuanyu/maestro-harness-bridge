# U2 项目设置验收

## 自动场景

先从本分支重新构建，在沙箱外运行：

```sh
npm run build
MAESTRO_E2E_REAL=0 npx playwright test e2e/native-project-settings.spec.ts --workers=1 --retries=0
```

`native-project-settings.spec.ts` 使用 `NativeApp` 的临时项目、Maestro 数据和工具账户，明确拒绝真实模式。不会向对话发送提示，不调用真实模型，不读取个人账户。用例失败后保留失败结果和 trace，不自动重试。

场景覆盖：

1. 新界面项目行右键打开设置，选择默认工具与模型。
2. 第一次完全访问需要勾选说明；凭据变量输入默认遮盖，保存后 CLI 默认遮盖，显式 `--show-secrets` 可读原值。
3. CLI 新建按项目设置创建对话；环境变化创建独立内部配置，旧对话的模型、只读权限和账户不变，新对话不会被项目的完全访问放宽。
4. 同一路径的两个 SSH 主机设置隔离。此项只读写 Maestro 设置，不建立 SSH 连接。
5. 重启后设置保留，通用快照不含环境原值，新建仍通过专用服务取得项目环境；默认工具改为沿用后仍保留模型所属工具。切换中文可看到“项目设置”；关闭新界面后普通新建不采用项目模型。
6. CLI 和 IPC 的通用设置写入都拒绝项目设置键，不能绕过首次完全访问说明。合成 Codex 回合计数文件未出现，证明本场景没有发送回合。

本轮未启动 Electron。构建后运行上述原名场景，不能将单元测试通过当作应用启动或界面验收通过。

## 补充人工场景

继续使用临时 Maestro 数据、合成账户和临时项目，不切入日常数据目录，不发送任何对话内容。

- 将同一项目的两家工具放到不同窗口。在项目设置中选择另一家工具，点击“按项目默认设置新建”，检查实际归属、焦点和 CLI 返回的归属 ID。再从当前对话新建，检查当前工具、账户、模型和强度优先，权限取更严格值。关闭来源所属窗口时，不能从缺失的当前对话快照放行。
- 修改项目环境后新建，再清空环境覆盖后新建。确认旧对话始终保留原环境，新对话恢复工具原始环境。保留停用变量状态。
- 在两个可丢弃的 SSH 测试主机和本机使用同样的目录文本。保存各自默认值并新建，核对执行目录和主机没有串用，`~` 没有被本机展开。不调用模型；远程工具探测可以使用合成可执行文件。检查较慢探测没有触发原来 5 秒的新建超时。
- 通过 Electron 中无 preload 的普通浏览器窗口打开临时 web-desktop，分别让配置清单先到和新建响应先到，确认新对话归属正确，原工具下面没有重复对话。实际手机键盘和焦点仍需设备验收。
- 给项目增加原配置没有的变量，从命令面板选择“在下方新建 AI 对话”，检查返回归属的环境及右侧分屏。原配置和已有对话不变。
- 在中英文下检查字段、首次权限说明、环境变量显隐和无效变量的保存禁用。切换新旧界面，检查旧的工具配置入口与已有对话仍可用。

## 已知边界

项目有默认值时，可达的分屏新建共用项目创建服务，并通过实际返回的归属调用 U1 分屏服务。CLI 用 `tab new` 后接 `tab split`；原子化动作的缺口登记在 `docs/agent-guides/CLI-UI-PARITY.md`。向导入口在新界面隐藏，未为其增加项目环境逻辑。浏览器设置响应不含项目环境值，浏览器只能编辑其他字段。

真实 SSH、多窗口、手机操作、其他操作系统和发行包均未在本轮执行。CLI 带提示的新建及目标窗口排队只做了 mock 回归，没有真实发送。
